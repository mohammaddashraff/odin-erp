## Implementation coordination

Reuse the existing Customer → Av8Lead → Av8Application identity chain, tenant transactions, `once` idempotency helper, scoped `application` lookup, permission registry, Av8Record for versioned operational events, private Av8Attachment bytes and evidence audit. Do not replace the Classic Sidebar or authentication/finance engine.

Academic delivery requires persistent recipient rows with a unique report-version/recipient identity and a worker claim. A JSON status alone cannot prove an external email occurred. Snapshot only the reviewed academic report and approved academic attachments; never attach all application documents. A timeout after request transmission must remain unknown until reconciled; it must not immediately replay. Keep fixture provider behavior distinct from verified real-provider delivery.

Financial/domain implementation is coordinated separately. Operational work must not add automatic fees, alter contract date anchors, decide refund eligibility or waive balances.
