# Client acceptance rehearsal

This is the client-executed UAT script, not a claim of client sign-off. Automated and browser evidence already executed is listed separately in [05-test-results-and-evidence.md](05-test-results-and-evidence.md). Run in the isolated acceptance environment with named management, sales, affairs, finance and approver accounts. Use synthetic people, controlled attachments and approved policy fixtures. Do not send to real students or create real bank instructions during rehearsal. Record the exact deployed commit, migration version, tester/role, date, result and evidence ID for every step.

Before starting, the business owner confirms the remaining decisions in [02-business-rules-and-decisions.md](02-business-rules-and-decisions.md), the original accounting mappings, resource permissions, fee/cheque/refund selections and each signed-plan schedule. A missing decision blocks its dependent transaction, while unrelated work continues. Named finance journal approval also requires `journal.lines` field view/edit and the actual account/resource assignments; a permission name alone does not grant hidden financial fields.

## Controlled provider rehearsal

The current delivery's automated provider tests are mocks. The administrator must first authorize two controlled test addresses, configure a verified sender and provider key privately, and restrict nonproduction to those exact addresses. Use a synthetic academic report only. Follow the states and retry/reconcile guidance in [08-admin-and-support-runbook.md](08-admin-and-support-runbook.md). Never infer delivered/read from HTTP acceptance. If credentials, hosting scheduler or real alert destination are unavailable, mark the relevant external result BLOCKED with owner/action; continue the remaining cases.
